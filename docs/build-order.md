# 아쉬베일 연대기 — 작업 순서

기획서(`game-design-doc.md` v1.0)를 실제로 구현하는 순서.
**핵심 원칙: 기획서를 한 번에 다 주지 않는다.** 단계마다 해당 절만 붙여서 지시하고, 끝나면 폰에서 확인한 뒤 다음으로 넘어간다.

---

## 0단계 · 지금 정할 것 (10분)

기획서 §13에 결정 26개가 있는데, **대부분은 기본 제안대로 두면 된다.** 네가 직접 답해야 하는 건 둘뿐이다.

| 결정 | 질문 | 왜 지금인가 |
|---|---|---|
| **#11 연심 배타성** | 동시에 연인은 1명만? 아니면 여러 명 가능? | 1명이면 "누구를 고를까"의 게임, 다수면 "모으는" 게임. 성격이 갈리므로 §7 구현 전에 필요 |
| **#2 LLM 서사** | 사전 작성 텍스트만 쓸까? | "예"로 확정해야 §12.8 비통신 보장이 성립. 나중에 뒤집으면 구조가 바뀐다 |

나머지는 문서의 기본 제안을 그대로 따르면 된다. 기획서 맨 앞에 한 줄로 적어두면 구현 에이전트가 참조한다.

---

## 1단계 · 준비물 (1회, 30분)

- **Node.js** 설치 (LTS)
- **Claude Code** 설치
- 빈 폴더 만들고 `git init`
- 폴더 안에 `docs/` 만들어 기획서와 이 파일을 넣기
- GitHub 저장소 생성 (배포와 APK 빌드에 쓴다. 비공개로 둬도 된다)

> 안드로이드 SDK, Android Studio, JDK는 **지금 필요 없다.** 8단계에서 APK를 만들 때만, 그것도 GitHub Actions를 쓰면 안 깔아도 된다.

## 2단계 · 골격 (M0~M1)

**목표:** 폰에서 열리고, 세이브가 남고, 격자를 손가락으로 확대·이동할 수 있다. 그림은 아직 색 사각형.

**클로드 코드에 줄 것:** 기획서 §0, §3, §10.1~10.4, §12.1~12.4, §12.8

**지시 예시**

```
docs/game-design-doc.md 의 §0, §3, §10.1~10.4, §12.1~12.4, §12.8 만 읽고
M0과 M1을 구현해줘. 다음 마일스톤의 시스템은 절대 미리 만들지 마.

- Vite + React + TS + Tailwind + Phaser 3, zustand
- GameState 타입과 시드 RNG
- StorageAdapter 인터페이스와 WebStorageAdapter (localStorage + IndexedDB)
- PWA 매니페스트 + 서비스 워커 + storage.persist() 요청
- 에셋 매니페스트와 플레이스홀더 렌더러 (?debugAssets=1 포함)
- 32색 팔레트를 src/data/palette.ts에 고정
- 393x852dp 세로 화면 기준 레이아웃, 핀치 줌/팬/더블탭/LOD

§12.8을 반드시 지켜: CDN 참조, 분석 도구, 크래시 리포팅을 넣지 마.
폰트는 번들해.
```

**완료 확인**
- [ ] 새 게임 → 새로고침 → 상태 복원됨
- [ ] 폰에서 홈 화면 추가되고 오프라인으로 열림
- [ ] 격자를 핀치로 확대/축소, 드래그로 이동, 더블탭으로 전체 보기
- [ ] DevTools 네트워크 탭에 초기 로딩 후 요청 없음

## 3단계 · 게임이 되는 지점 (M2~M6)

**목표:** 여기서 처음 "플레이"가 된다. 턴을 돌리고 건물을 올리고 탐험하고 레벨업한다. 그림은 여전히 플레이스홀더.

**한 번에 시키지 말고 M2 → M3 → M4 → M5 → M6 순으로 쪼갠다.** 각 마일스톤이 끝나면 직접 10~20턴 돌려본다.

| 마일스톤 | 붙일 절 | 확인 |
|---|---|---|
| M2 턴 엔진·자원·계절·연대기 | §2, §5(식량 수지), §9 | 휴식만으로 10주 진행, 계절에 화면 색이 바뀜 |
| M3 건설·인구·건물 3단계·주민 워커 | §5, §10.4 | 건물 올리면 스프라이트가 커지고 워커가 늘어남 |
| M4 시대 전환·맵 확장 연출 | §5(시대 테이블) | 시대 2 도달, 줌아웃 연출 |
| M5 탐험·판정 연출·레벨업 | §4, §6, §10.4 | 주사위값과 보정이 화면에 단계적으로 보임 |
| M6 스킬 트리·능력치·유물 | §4, §9 | 스킬 랭크가 판정 숫자에 반영됨 |

> **이 단계가 제일 중요하다.** 그림 없이도 재미있으면 만들 가치가 있는 게임이고, 재미없으면 그래픽을 붙여도 안 살아난다. M6 끝나고 30분쯤 플레이해보고 판단할 것.

## 4단계 · 사람 (M7~M7c)

**목표:** 관계 대상과 의뢰인이 등장하고, 네가 이미지를 넣을 수 있다.

**붙일 절:** §7 전체, §11.4~11.5

**M7 → M7b → M7c로 쪼갠다.** 특히 M7b(이미지 파이프라인)는 함정이 많아서 따로 확인해야 한다.

**M7b 완료 확인 — 이건 꼭 직접 해볼 것**
- [ ] 사진첩에서 이미지 추가 → 표시됨
- [ ] **사진첩 원본을 삭제 → 게임 내 이미지가 그대로 남아 있음** (§11.4 원본 참조 금지가 지켜졌는지 검증)
- [ ] 세로 사진이 눕지 않음 (EXIF 회전 처리)
- [ ] 갤러리 앱을 열어 게임 이미지가 안 보이는지 확인 (§11.5)
- [ ] 인물 화면을 5분간 열어둬도 앱이 무거워지지 않음 (objectURL 누수)

## 5단계 · 위협과 사건 (M8)

**붙일 절:** §8, §9

위협 승리와 패배를 양쪽 다 경험해봐야 한다. 성벽 레벨이 화면에서 실제로 두꺼워지는지 확인.

## 6단계 · 에셋 (M9) — 여기서 네 작업이 생긴다

지금까지는 클로드 코드가 다 했지만, **그림은 네가 조달해야 한다.** 이 단계는 3~5단계와 병렬로 진행할 수 있다.

**네가 할 일**

1. **CC0 타일셋 고르기** (Kenney.nl, itch.io). 가능하면 단일 팩. 지형 40 + 건물 36 + 성벽 24 + 캐릭터 20 정도
2. **일러스트 18장 만들기** — 지역 배경 6(세로 900×1200), 유물 아이콘 12(128×128). 프롬프트에 구도·재질감·조명·팔레트를 고정 접두로 두고 **전량을 같은 세션에서** 만들 것. 스타일 일관성이 유일한 과제
3. **관계 대상 이미지** — 개수 제한 없이 네가 원할 때. 슬롯이 열릴 때마다 추가

**클로드 코드가 할 일:** 팔레트 리맵 스크립트, 텍스처 아틀라스 묶기, 매니페스트 교체

**완료 확인:** `?debugAssets=1`에 자홍색 외곽선이 남지 않음

---

## 7단계 · 배포와 실제 플레이 (M10)

**목표:** 폰에 앱처럼 설치해서 실제로 플레이 시작.

1. GitHub Pages(또는 Cloudflare Pages)에 정적 배포
2. 폰 Chrome으로 열어 **홈 화면에 추가**
3. 비행기 모드로 전체 기능 한 바퀴 (§12.8 검증)
4. 번들에서 `http://`, `https://` 문자열 검색해 런타임 참조 없는지 확인

**주의:** 이후 코드를 고쳐 **같은 주소**에 재배포하면 세이브는 유지된다. **주소를 바꾸기 전에는 반드시 꾸러미를 내보낼 것** (§12.7).

여기서 멈춰도 완성이다. 8단계는 필요해지면 하면 된다.

## 8단계 · APK (M11, 선택)

**언제 하면 되나:** 브라우저 데이터가 지워져 세이브를 잃은 적이 있을 때, 이미지가 쌓여 잃을 게 커졌을 때, 호스팅 의존을 없애고 싶을 때.

**붙일 절:** §12.6, §12.7, §12.9, §11.5

**지시 예시**

```
M11을 구현해줘. Capacitor 셸을 씌우고 CapacitorAdapter를 추가해.
게임 로직은 수정하지 마 — StorageAdapter 교체만으로 끝나야 해.

- 이미지와 세이브는 Directory.Data 에만 쓴다 (§11.5, 갤러리 노출 방지)
- 이미지 선택은 시스템 포토 피커. READ_MEDIA_IMAGES 권한 요청 금지
- AndroidManifest에서 android.permission.INTERNET 제거 (§12.8)
- 로컬 SDK 없이 빌드할 GitHub Actions 워크플로도 작성.
  키스토어는 base64로 저장소 비밀값에 넣고 저장소에 커밋하지 마
- 키스토어 생성과 백업 절차를 README에 남겨
```

**완료 확인**
- [ ] APK 설치 → 플레이 → 앱 재시작 후 세이브·이미지 유지
- [ ] 앱 권한 목록에 `INTERNET` 없음
- [ ] 코드 고쳐 같은 키로 재서명한 APK를 덮어 설치 → 데이터 유지
- [ ] **키스토어 파일과 비밀번호를 따로 백업했다** ← 이걸 잃으면 업데이트가 불가능하고, 재설치하면 이미지가 다 사라진다

## 하지 말 것

1. **기획서 전체를 한 번에 주지 않는다.** 1013줄을 통째로 넣으면 초반 마일스톤에서 뒤쪽 시스템까지 미리 구현하려 들어 구조가 엉킨다
2. **마일스톤을 건너뛰지 않는다.** 특히 M0의 `StorageAdapter`와 플레이스홀더 렌더러 — 나중에 붙이면 이미 늦다. 마이그레이션 함수도 마찬가지
3. **그래픽을 먼저 붙이지 않는다.** 3단계에서 플레이스홀더로 재미를 확인한 다음에 에셋을 넣는다. 순서를 바꾸면 재미없는 게임에 그림을 칠하게 된다
