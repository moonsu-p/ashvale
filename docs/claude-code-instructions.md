## 0. 파일 배치 (한 번만)

`ashvale.zip`을 풀면 이미 이 구조로 되어 있다. 별도 배치 작업이 필요 없다.

```
ashvale/
├─ docs/
│   ├─ game-design-doc.md          ← 기획서 (본문)
│   ├─ claude-code-instructions.md ← 이 문서

│   ├─ ASSETS.md
│   └─ illustration-prompts.md
├─ src/data/
│   ├─ palette.ts
│   ├─ assets.ts
│   └─ content/
│       ├─ companion-dialogue.ts
│       ├─ patron-dialogue.ts
│       ├─ dialogue-events.ts
│       ├─ region-text.ts
│       └─ world-content.ts
└─ scripts/
```

`src/`와 `scripts/`는 아직 프로젝트가 없어서 폴더만 있는 상태다. 정상이다. M0에서 클로드 코드가 나머지를 채운다.

## 0.5 시작하기 (윈도우 · Claude 데스크톱 앱)

### 미리 설치할 것

Claude Code는 데스크톱 앱에 포함되어 있어 CLI를 따로 깔 필요가 없다. 다만 이 프로젝트는 두 가지가 더 필요하다.

| | 왜 | 어디서 |
|---|---|---|
| **Node.js LTS** | Vite 개발 서버와 npm | nodejs.org |
| **Git for Windows** | 버전 관리, 나중에 GitHub 배포 | git-scm.com |

둘 다 설치 화면에서 기본값으로 계속 다음을 누르면 된다. 없으면 첫 메시지에서 클로드 코드가 알려준다.

### 폴더 준비

1. `ashvale.zip`을 **압축 풀기**한다 (우클릭 → 압축 풀기)
   윈도우는 zip 안을 폴더처럼 미리보기 해주는데, **그 상태로는 클로드 코드가 파일을 못 본다.** 반드시 실제로 풀 것
2. 위치는 **`C:\dev\ashvale`** 를 권한다
   - 문서·바탕화면은 OneDrive 동기화가 걸린 경우가 많다. `npm install`이 파일 수천 개를 만들면 동기화가 충돌하고 느려진다
   - 경로가 짧으면 `node_modules` 깊이가 윈도우 경로 길이 제한에 걸리는 것도 피할 수 있다

### 앱에서 열기

1. Claude 앱 상단 중앙의 **Code** 탭
2. **Local** 선택 (내 컴퓨터의 파일로 작업)
3. **Select folder** → `C:\dev\ashvale`

### 승인 모드

Code 탭은 기본적으로 Manual 모드로 시작해 변경마다 승인을 기다린다. M0은 파일이 많이 생성되어 승인이 번거로울 수 있지만 **처음에는 그대로 두는 것을 권한다** — 무엇을 만드는지 보는 것이 이 단계의 목적이다. M2쯤부터 자동 승인으로 올려도 된다.

### git

git은 따로 배울 필요 없다. 클로드 코드가 직접 실행한다. 다만 **코드가 생기기 전에 문서만 있는 상태로 첫 커밋을 남긴다.** 나중에 되돌릴 기준점이 된다.

아래를 그대로 첫 메시지로 넣는다.

```
이 폴더는 새 게임 프로젝트야. 코드는 아직 없고 문서와 데이터 파일만 있어.

- docs/game-design-doc.md : 기획서 1300줄. 지금 전체를 읽지 마.
- docs/claude-code-instructions.md : 내가 너에게 줄 지시 순서. 이건 읽어도 돼.
- src/data/*.ts 와 src/data/content/*.ts : 완성된 데이터·대사 파일. 읽기만 하고 수정하지 마.
- scripts/remap-palette.ts : 빌드 전 실행용. 지금은 건드리지 마.

먼저 이것만 해줘:
0. node --version 과 git --version 을 확인해서 둘 다 설치돼 있는지 알려줘. 없으면 어디서 받아야 하는지만 말해주고 멈춰
1. git 저장소 초기화
2. .gitignore 작성 — node_modules, dist, .env, *.keystore, *.jks 는 반드시 제외.
   raw-assets/ 는 CC0 타일셋 원본이 들어갈 자리니까 제외하지 마
   그리고 .gitattributes 에 "* text=auto eol=lf" 를 넣어줘 (윈도우 줄바꿈 변환 문제 방지)
3. 지금 상태를 "docs: 기획서와 콘텐츠 데이터 추가" 로 첫 커밋
4. 파일이 다 있는지 구조를 확인해서 보고

코드는 아직 만들지 마. 다음 메시지에서 M0을 지시할 거야.
```

### git 습관 두 가지

1. **마일스톤이 끝날 때마다 "커밋해줘"** 라고 말한다. 마일스톤 단위로 되돌릴 수 있게 된다
2. 망가졌을 때는 `git log --oneline`으로 확인하고 되돌린다. 이것도 클로드 코드에게 "M3 커밋으로 되돌려줘"라고 말하면 해준다

`.keystore`와 `.jks`를 .gitignore에 넣는 것이 특히 중요하다. APK 서명 키이며, 저장소에 올라가면 비공개라도 위험하고 GitHub Actions에서는 비밀값으로 주입해야 한다(§12.9).

## 1. 모든 지시에 붙일 공통 규칙

**매번 지시문 끝에 이 블록을 붙인다.** 클로드 코드가 마일스톤을 넘어 앞서가는 것을 막는 장치다.

```
공통 규칙:
- 지정된 절만 읽어라. 기획서 전체를 읽지 마라.
- 이번 마일스톤 범위를 넘어서 구현하지 마라. 다음 마일스톤 시스템의 자리만 비워두는 것도 하지 마라.
- 규칙 로직은 src/systems/ 의 순수 함수로. React 컴포넌트나 Phaser 씬에 게임 규칙을 넣지 마라.
- 수치는 전부 src/data/*.ts 상수로. 코드에 숫자를 박지 마라.
- src/data/ 안의 기존 파일(palette.ts, assets.ts, content/*)은 읽기만 하고 수정하지 마라.
- 색은 palette.ts 에서만 가져와라. Tailwind 기본 팔레트를 쓰지 마라.
- CDN 참조, 분석 도구, 크래시 리포팅을 넣지 마라 (기획서 §12.8).
- localStorage / indexedDB 를 StorageAdapter 밖에서 직접 호출하지 마라.
- 작업이 끝나면 무엇을 만들었는지와 완료 조건 충족 여부를 짧게 보고해라.
```

## 9. 하지 말 것

1. **기획서 전체를 한 번에 주지 않는다.** 1300줄을 통째로 넣으면 초반 마일스톤에서 뒤쪽 시스템까지 미리 구현하려 들어 구조가 엉킨다
2. **마일스톤을 건너뛰지 않는다.** 특히 M0의 StorageAdapter·플레이스홀더 렌더러·마이그레이션 함수. 나중에 붙이면 이미 늦다
3. **content/ 파일을 클로드 코드가 고치게 하지 않는다.** 대사와 서술은 완성본이다. 고치라고 하면 톤이 무너진다
4. **배포 주소를 바꾸기 전에 꾸러미를 내보낸다.** 출처가 바뀌면 세이브가 따라오지 않는다 (§12.7)
5. **§13의 결정을 임의로 바꾸지 않는다.** 바꿀 필요가 생기면 표를 갱신하고 영향받는 절을 함께 고친다
